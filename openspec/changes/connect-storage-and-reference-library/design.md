# Design

## Context

参见 proposal.md。原有项目为 Next.js App Router，本变更接入真实认证与 SQLite。七位角色的 37 张本地采集图片及 JSON 索引已存在。目标 COS 对象读写实测成功，但当前密钥无桶配置查询权限。用户明确要求正式登录，并将这些采集资料作为公共素材。

## Goals / Non-Goals

**Goals:** 形成账号、用户素材、公共人物、对象存储之间的实际可验证链路。

**Non-Goals:** 本次不接生成服务、MMD 播放器、邮件投递和 OAuth 服务，不假设 CDN 已开通。邮箱密码账号不声称已完成邮箱归属验证。

## Decisions

1. Better Auth + Node.js 内置 SQLite：使用现有 Node 26 环境，无需额外托管数据库或原生编译依赖。注册、密码散列、会话 cookie 交给成熟认证库；当前以邮箱密码登录，不依赖缺失的 OAuth/邮件服务凭据。生产采用有持久磁盘的 Node 运行环境，SQLite 不能直接部署在易失的无服务器文件系统。
2. 文件采用 S3 SDK，临时凭据采用腾讯云 STS，复用 demotif 凭据仅写入 hachimi 的私有环境文件。按用户和上传 UUID 分配键，临时策略覆盖单个对象及必要分片动作。完成接口校验归属和 HEAD 大小，再将记录从 pending 改为 ready。
3. 用户素材元数据与认证数据保存在项目 SQLite；首批七位角色的 37 张图片位于 public/materials/builtin/，目录和来源元数据保存在 references/characters/catalog.json，随代码分发。内置素材使用稳定静态路径和 builtin 身份，不依赖登录、COS 或 STS；复制入库时按原目录 SHA-256 核验。用户对象仍保存在 COS，不把任何密钥序列化到页面。
4. 上传使用 S3Client 处理 File/Blob；分片初始化与完成由服务端负责。CORS 只在 COS 实际边界配置应用来源；不复制 demotif 的无关校验和抽象。若现有密钥无配置权限，清楚记录并请求目标桶配置，不擅自扩大账号权限。
5. 素材信息模型参考 Kling Element Library 的人物多图组合、Runway 的持久参考与标签、Firefly 的素材复用。第一版只保留人物身份、名称别名、画风、视角、来源、权限说明、图像尺寸、文件指纹和模型配布入口。素材库先展示内置人物；个人素材使用独立云盘入口，内置和个人素材均通过回调带入创作。
6. 未提供 CDN 域名，用户文件先采用签名 COS GET URL；部署配置媒体域名后可替换访问地址返回策略，文件无需移动。URL 不当作素材身份保存，避免链接过期导致元数据失效。

## Risks / Trade-offs

- SQLite 要求持久卷及单实例写入环境，需要在部署说明中明确。
- 对象 HEAD 大小不等于内容散列，采集导入使用本地 SHA-256 元数据与 GET 回读核验；用户上传确认不谎称已验完整文件摘要。
- 同一文件在不同画风或来源下仍需保留独立资料记录，物理对象可共享。
- CDN 尚未提供配置，真实播放加速不作为本次完成状态。

## Migration Plan

安装依赖、配置独立环境文件、运行认证数据库迁移、将内置资料纳入版本控制、启动服务验证真实上传与身份隔离。回滚应用代码不删除 COS 素材和数据库；如需撤销上传能力，只停止签发新凭据，已签发 STS 至有效期结束。

## Built-in Library Update

2026-11-09 用户明确要求首批素材随代码分发。侧栏名称改为素材库，四语同步；人物详情按原版、可爱和模型分组，仅提供角色库，不分发或展示公共设定预览。模型仍仅展示配布入口，不下载二进制。内置图片可选择为创作参考，不声称已调用生成服务。

## Typography and Search

全站采用站酷快乐体的本地 WOFF2 版本，缺字由寒蝉全圆体补充；均保留 OFL 授权。转换后的寒蝉字体改名 Hachimi Rounded，避免使用上游保留字体名称。全站主题字体统一应用，不调整字距。素材库搜索使用全宽表单与右侧按钮，点击或回车提交，清空恢复全部角色；内置标记属于角色卡片和角色详情，不属于素材库总标题。

## Sidebar Layout Review

页面框架复用官方 radix-nova/sidebar-07 的 SidebarProvider、SidebarInset、64px 顶部栏与内层 flex 布局。垂直分隔线沿用官方 `data-vertical:h-4 data-vertical:self-auto`，覆盖 primitive 的 self-stretch。导航使用项目业务入口，语言与主题按钮仍分开；未引入示例团队、订阅方案或多级面包屑。内容区采用统一 16px/24px 间距，主内容仅保留 SidebarInset 一个 main。手机导航选择后由业务侧关闭抽屉。角色卡片是业务布局，不宣称复刻官方 block。

根据用户明确偏好，全站点击均触发局部彩屑，包含导航、搜索和偏好菜单；系统开启减少动态效果时不触发。移除全局对按钮 active 位移的覆盖，让组件保留自身反馈。

## Navigation Update

主导航依次为创作、发现、角色、资产；搜索框放在发现页内，不提供独立搜索入口；我的空间仅包含我的作品与我的收藏。现有角色图库归入角色入口，创作选择参考从角色进入。资产使用独立标识并接入个人云盘。所有入口名称及相关状态支持四语。

## Personal Drive and Quota

资产成为真实个人云盘。默认配额 10GB = 10,000,000,000 字节，SQLite 保存文件夹与对象索引，COS 前缀为 users/<userId>/assets/。单实例数据库事务同时核对并预留容量；有效 pending/cancelled/deleted 租约预留与 ready 文件一同计入容量，避免凭据仍可写时过早释放额度。凭据到期后在该用户后续资产请求中清理临时对象或未完成分片。

普通上传使用仅单对象 PutObject 的 15 分钟 STS，条件限制 Content-Length 不超过预留大小并要求禁止覆盖头。大文件分片由服务端初始化和完成，临时凭据仅可 UploadPart，服务端 ListParts 检查序号和总大小后 CompleteMultipartUpload。完成接口 HEAD 核对大小并幂等登记。删除 ready 文件后释放占用；凭据尚有效的同一键仍暂时保留对应预留，期限届满后清理。配额是应用已登记文件与上传租约的逻辑容量，不声称 COS 提供按前缀硬配额。

云盘支持文件夹、搜索、多文件上传、下载、删除和选作参考。只验证认证、对象归属、配额与文件大小，不新增文件类型白名单或跨域业务检查。服务端 readAsset(userId, assetId) 只读取该用户 ready 资产，供后续创作 agent 复用；不预建 agent 引擎。
